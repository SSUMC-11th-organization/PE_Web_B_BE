# 6주차 구현 검증 결과

## 자동 검증

`movie/`에서 `gradlew.bat test bootJar` 실행 성공.

| 테스트 | 건수 | 결과 |
| --- | --- | --- |
| MemberApiTests (기존 조회/검증/CORS) | 6 | 통과 |
| CorsDisabledTests (CORS 미설정 재현) | 1 | 통과 |
| Week6ApiTests (쓰기 API) | 14 | 통과 |
| 합계 | 21 | 실패 0 |

6주차 테스트에서 다음을 확인했다.

- 회원가입 201, 비밀번호 응답 제외, DB에 60자 bcrypt 해시 저장, 원본 비밀번호와 matches 성공.
- 중복 이메일/닉네임 409, 추가 회원이 저장되지 않음.
- 이메일/비밀번호/닉네임 누락·형식 오류 400, bcrypt 최대 입력 바이트 검사.
- 사전 중복 확인을 테스트 대역으로 통과시켜도 실제 DB UNIQUE 제약이 저장을 막고 일관된 409를 반환함. 실제 동시 요청을 실행했다고 기록한 것은 아님.
- 평점 등록 → 조회 → 수정 → 조회 → 삭제 204/빈 본문 → 빈 목록 조회.
- 중복 평점 409 및 DB에 한 건만 유지.
- 없는 회원·평점 404, 다른 회원의 수정과 삭제 403, 원래 데이터 유지.
- 잘못된 movieId/score, 소수 movieId/score, 후기 길이, 누락 필수값 400.
- 선택 후기 null 처리, 잘못된 JSON·경로 타입의 공통 400 응답.
- 지정 Origin의 POST/PATCH/DELETE preflight 성공 및 금지한 Origin/PUT 차단.
- Swagger OpenAPI 문서에서 4개 쓰기 API 노출.

## 트러블슈팅

기존 GET 전용 CORS에서 쓰기 preflight 테스트 실패(기대 200 / 실제 403)를 실제 재현했다. 필요한 메서드를 허용한 뒤 같은 테스트가 통과했다. 상세 기록은 [week6-troubleshooting.md](week6-troubleshooting.md).

## 검증 범위와 남은 작업

자동 검증은 H2 MySQL 호환 모드로 수행했다. 사용자가 제공한 로컬 Swagger 캡처에서 회원가입 201, 중복 이메일 409, 평점 등록 201, 수정 200, 삭제 204를 확인했다. 삭제 인증은 평점 4번 삭제 후 새로 등록한 평점 5번으로 수행했다. 실제 400·403·404 응답 캡처는 별도 확인이 필요하다.

요청/응답 및 캡처 순서는 [미션 가이드](week6-mission.md)를 참고한다. 5주차 테이블과 데이터를 그대로 사용하며 별도 스키마 변경은 없다. 6주차 작업 이슈는 #31, 제출 브랜치는 `mins/#31`이다. Notion 게시와 PR 생성은 사용자가 진행한다.
